# Data Model: BFIS Snapshot Ingestion & Binary Decoding

**Date**: 2025-11-16  
**Feature**: 001-bfis-snapshot-decoders

## Overview

This document defines the data entities, relationships, and validation rules for BFIS snapshot ingestion. Entities are organized into:
1. **Shared Schemas** (in `shared-schemas/index.ts`) - BFIS ⇄ Olympus contract
2. **Internal Types** (in `bfis-service/src/types/internal.ts`) - BFIS-only implementation details

## Entity Definitions

### 1. OlympusSnapshot (Shared Schema)

**Location**: `shared-schemas/index.ts`  
**Purpose**: Represents a point-in-time view of the battlefield state as reported by Olympus. This is the primary output of `SnapshotReader.readOnce()`.

**Fields**:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `snapshotId` | `string` | Yes | UUID v4 identifier for this snapshot (generated by BFIS) |
| `missionId` | `string` | Yes | Mission identifier from Olympus `/olympus/mission` response |
| `serverId` | `string` | Yes | Server identifier from Olympus `/olympus/mission` response |
| `sessionHash` | `string` | Yes | Olympus session hash used to detect mission resets |
| `time` | `string` | Yes | ISO 8601 timestamp of snapshot creation (from latest endpoint response) |
| `units` | `OlympusUnit[]` | Yes | Array of decoded units (always present, may be empty) |
| `events` | `OlympusEvent[]` | No | Optional derived events from logs or snapshot diffing (MVP: optional) |

**Validation Rules**:
- `snapshotId` must be valid UUID v4 format
- `units` array must always be present (may be empty array)
- `sessionHash` must match the session hash from the latest endpoint response
- `time` must be valid ISO 8601 timestamp

**State Transitions**: Immutable once created (FR-018). New snapshots created on each `readOnce()` call.

**Relationships**:
- Contains multiple `OlympusUnit` entities
- Optionally contains `OlympusEvent` entities
- Referenced by future `BfisDecision` entities (separate spec)

---

### 2. OlympusUnit (Shared Schema)

**Location**: `shared-schemas/index.ts`  
**Purpose**: Represents a single unit on the battlefield. Decoded from binary `/olympus/units` endpoint.

**Fields**:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `unitId` | `string` | Yes | Unique unit identifier (converted from uint32 in binary) |
| `groupId` | `string` | No | Group identifier if unit belongs to a group (converted from uint32) |
| `name` | `string` | No | Unit display name |
| `coalition` | `OlympusCoalition` | Yes | Unit coalition (BLUE, RED, NEUTRAL, UNKNOWN) |
| `category` | `string` | Yes | High-level category (e.g., "Aircraft", "Helicopter", "GroundUnit", "NavyUnit") |
| `unitType` | `string` | Yes | Specific unit type (e.g., "F-16C_50", "AH-64D") |
| `position` | `OlympusUnitPosition` | Yes | Unit position (lat, lon, altitude) |
| `status` | `string` | No | Unit status/state (e.g., "idle", "attack", "follow") |

**Validation Rules**:
- `unitId` must be non-empty string (converted from uint32, never null)
- `coalition` must be one of: "BLUE", "RED", "NEUTRAL", "UNKNOWN"
- `position.lat` must be valid latitude (-90 to 90)
- `position.lon` must be valid longitude (-180 to 180)
- `position.altMeters` must be non-negative number

**Decoding Source**: Binary buffer from `GET /olympus/units?time={t}`  
**Decoding Pattern**: See `frontend/react/src/unit/unitsmanager.ts:234-266` and `frontend/react/src/unit/unit.ts:590-831`

**Relationships**:
- Belongs to `OlympusSnapshot` (many-to-one)
- May belong to a group (via `groupId`)

---

### 3. OlympusUnitPosition (Shared Schema)

**Location**: `shared-schemas/index.ts`  
**Purpose**: Represents a 3D position for a unit.

**Fields**:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `lat` | `number` | Yes | Latitude in decimal degrees (-90 to 90) |
| `lon` | `number` | Yes | Longitude in decimal degrees (-180 to 180) |
| `altMeters` | `number` | Yes | Altitude in meters above sea level (non-negative) |

**Validation Rules**:
- `lat`: -90 ≤ value ≤ 90
- `lon`: -180 ≤ value ≤ 180
- `altMeters`: value ≥ 0

**Decoding Source**: `DataExtractor.extractLatLng()` returns `BfisLatLng` which is converted to `OlympusUnitPosition` (threshold field ignored).

---

### 4. OlympusCoalition (Shared Schema)

**Location**: `shared-schemas/index.ts`  
**Purpose**: Type-safe coalition identifier.

**Type**: `"BLUE" | "RED" | "NEUTRAL" | "UNKNOWN"`

**Decoding Source**: `DataExtractor.extractUInt8()` converted via `enumToCoalition()` helper (matches frontend pattern).

---

### 5. OlympusEvent (Shared Schema)

**Location**: `shared-schemas/index.ts`  
**Purpose**: Represents a battlefield event derived from logs or snapshot diffing.

**Fields**:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `eventId` | `string` | Yes | Unique event identifier (generated by BFIS) |
| `time` | `string` | Yes | ISO 8601 timestamp of event |
| `type` | `string` | Yes | Event type (e.g., "unit_destroyed", "unit_spawned", "mission_start") |
| `unitId` | `string` | No | Associated unit ID if applicable |
| `details` | `Record<string, unknown>` | No | Additional event-specific data |

**Validation Rules**:
- `eventId` must be non-empty string
- `time` must be valid ISO 8601 timestamp
- `type` must be non-empty string

**Note**: Events are optional in MVP (FR-007 mentions "optional derived events"). Implementation may be deferred to post-MVP.

---

### 6. SessionState (Internal Type)

**Location**: `bfis-service/src/snapshot/snapshot-reader.ts` (private state)  
**Purpose**: Tracks polling state for session hash detection and incremental updates.

**Fields**:

| Field | Type | Description |
|-------|------|-------------|
| `lastSessionHash` | `string \| null` | Last known session hash (null on first poll) |
| `lastTimes` | `Record<string, number>` | Last update time per endpoint: `{ units: number, weapons: number, logs: number }` |

**State Transitions**:
- **Initial**: `lastSessionHash = null`, `lastTimes = {}`
- **After successful poll**: `lastSessionHash = snapshot.sessionHash`, `lastTimes` updated from response times
- **On session hash change**: `lastSessionHash` updated, `lastTimes = {}` (reset for full refresh)

**Validation Rules**:
- `lastTimes` keys must be: "units", "weapons", "logs"
- `lastTimes` values must be non-negative numbers (milliseconds since epoch)

---

### 7. BfisLatLng (Internal Type)

**Location**: `bfis-service/src/types/internal.ts`  
**Purpose**: Internal representation of lat/lng/alt from binary decoder. Converted to `OlympusUnitPosition` for snapshots.

**Fields**:

| Field | Type | Description |
|-------|------|-------------|
| `lat` | `number` | Latitude |
| `lng` | `number` | Longitude |
| `alt` | `number` | Altitude in meters |
| `threshold` | `number \| undefined` | Optional threshold value (from binary format, not used in snapshots) |

**Note**: Already implemented in `bfis-service/src/types/internal.ts`. Used by `DataExtractor.extractLatLng()`.

## Data Flow

### Snapshot Construction Flow

```
1. SnapshotReader.readOnce() called
   ↓
2. Fetch endpoints sequentially:
   - GET /olympus/mission → JSON (missionId, serverId, sessionHash, time)
   - GET /olympus/units?time={lastTime} → Binary buffer
   - GET /olympus/weapons?time={lastTime} → Binary buffer
   - GET /olympus/logs?time={lastTime} → JSON
   - GET /olympus/airbases → JSON
   - GET /olympus/bullseyes → JSON
   - GET /olympus/spots → JSON
   - GET /olympus/drawings → JSON
   ↓
3. Check session hash after each fetch (abort if changed)
   ↓
4. Decode binary buffers:
   - Extract updateTime (uint64, first 8 bytes)
   - Decode units using DataExtractor + unit-decoder
   - Decode weapons using DataExtractor + weapon-decoder
   ↓
5. Convert internal types to shared schemas:
   - BfisLatLng → OlympusUnitPosition
   - Internal unit data → OlympusUnit[]
   ↓
6. Construct OlympusSnapshot:
   - Generate UUID v4 snapshotId
   - Combine mission data + decoded units + optional events
   ↓
7. Update SessionState:
   - lastSessionHash = snapshot.sessionHash
   - lastTimes updated from response times
   ↓
8. Return immutable OlympusSnapshot
```

### Binary Decoding Flow (Units)

```
1. DataExtractor created from ArrayBuffer
   ↓
2. Extract updateTime: extractUInt64() (first 8 bytes)
   ↓
3. Loop while seekPosition < buffer.byteLength:
   a. Extract unitId: extractUInt32()
   b. If new unit:
      - Extract datumIndex: extractUInt8()
      - If datumIndex === DataIndexes.category:
        - Extract category: extractString()
        - Create new unit with unitId, category
   c. Update unit data:
      - Loop extracting datumIndex + value pairs
      - Switch on datumIndex to extract:
        * DataIndexes.coalition → extractUInt8() → convert to OlympusCoalition
        * DataIndexes.name → extractString()
        * DataIndexes.position → extractLatLng() → convert to OlympusUnitPosition
        * DataIndexes.unitID → extractUInt32() → convert to string
        * DataIndexes.groupID → extractUInt32() → convert to string (optional)
        * ... (other fields as needed)
      - Stop when datumIndex === DataIndexes.endOfData (255)
   ↓
4. Return array of OlympusUnit objects
```

## Validation Rules Summary

### Snapshot Validation
- ✅ `snapshotId` is valid UUID v4
- ✅ `units` array is present (may be empty)
- ✅ `sessionHash` matches latest endpoint response
- ✅ `time` is valid ISO 8601 timestamp
- ✅ All units have valid `unitId`, `coalition`, `position`

### Unit Validation
- ✅ `unitId` is non-empty string
- ✅ `coalition` is one of: BLUE, RED, NEUTRAL, UNKNOWN
- ✅ `position.lat` is in range [-90, 90]
- ✅ `position.lon` is in range [-180, 180]
- ✅ `position.altMeters` is non-negative

### Session State Validation
- ✅ `lastTimes` keys are: "units", "weapons", "logs"
- ✅ `lastTimes` values are non-negative numbers

## Relationships Diagram

```
OlympusSnapshot (1)
  ├── contains → OlympusUnit[] (many)
  │     └── has → OlympusUnitPosition (1)
  │     └── has → OlympusCoalition (1)
  └── contains → OlympusEvent[] (optional, many)

SessionState (internal, 1 per SnapshotReader instance)
  └── tracks → lastSessionHash, lastTimes
```

## Implementation Notes

1. **Type Conversions**: Internal types (`BfisLatLng`, etc.) are converted to shared schema types (`OlympusUnitPosition`, etc.) during snapshot construction. This keeps internal implementation details separate from the contract.

2. **Immutable Snapshots**: Once created, `OlympusSnapshot` objects are never mutated (FR-018). New snapshots are created on each poll cycle.

3. **Empty Data Handling**: Empty arrays (e.g., zero units) are valid and result in valid snapshots with empty `units` array. Warning logged per FR-014a.

4. **Session Hash Tracking**: Session hash is extracted from every JSON endpoint response (mission, logs, etc.). Binary endpoints don't include session hash, so it comes from the latest JSON response.

5. **Time Tracking**: `lastTimes` are updated from:
   - JSON responses: `time` field (string, converted to number)
   - Binary responses: Leading `uint64` updateTime (first 8 bytes)
